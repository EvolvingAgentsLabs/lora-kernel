## 0. The rule the day ran under

The plan was restructured bottom-up (`CLAUDE.md` §8, plan §0b): each layer is
validated alone, frozen with a test, and only then is the layer above built. **No
piece counts as working until it has a preflight, a persisted artefact, a test that
re-verifies it, and a failure condition written before it runs.** Three transversal
rules: freeze per piece; one unknown per run; the negative outcome is a deliverable.

## 2. What was not done, and why not — by kind of reason

### 2a. Blocked by measurement (the honest kind)

**The ordering verdict (M2) was never measured.** Its precondition,
$Q(T) \ge \max_a Q(E_a)$ (FOUNDATIONS §7.2), fails on both suites where it could be
bought: an untrained same-family 32B is **below** a 3B trained on 600 examples of the
task. And on the one suite where the target is strong (desk `commitment`, one call and
a copy), the trained grades **saturate** — `g75` ≡ `g600` = 1.000 — so the only
ordering left is *broken vs perfect*, which twelve keywords also resolve (P1). The
window the test needs — target ahead **and** a non-trivial ordering — exists in no
suite this project can generate. **Closed as the negative deliverable (decision D).**
One redesign of three remains and is reserved for a real-data suite with a verifier.

**The `--prune` accuracy delta is unresolved.** 87 : 64 is real in direction and lands
at $p = 0.073$; `bar.n_for(0.752, 0.05)` = 466 and 475 were run — sized at the edge,
landed on it. The behaviour difference is not in doubt (225 of 227 calls refused
against 8 of 1160).

### 2b. Blocked by design

**The route to `Qwen3.8-27B` (Phase 6).** D4 would point this instrument at a 27B with
a 3.5-4B drafter; with M2 closed it would buy a faster version of a mechanism with no
verdict. Not tokenizer (D0 is measured compatible), not C18 alone — the dependency.

## 4. Questions a reviewer should weigh

1. **The M-target gate is strict (`>`), the mathematics says `≥`.** On a saturated
   suite a tie at the ceiling can never pass. Should the code follow §7.2 literally?
   It would not have changed either verdict here (0 : 13 and 0 : 8 are losses), but it
   decides what a future ceiling reads as.
2. **Should α be measured anyway, as a *reported* number, against a weaker target?**
   The gate refused to buy it as a ranking; as a description of *where* a small expert
   agrees with a larger one it might still be informative. The instrument is built and
   preflighted; the run is ~15 minutes.
3. **Is `--prune`'s accuracy delta worth 466 more cases** to resolve at $p \le 0.05$,
   given the behaviour evidence already decides the default?
4. **The harness-as-LoRA experiment** (README, experimental extra): P55 A shows the
   *decision* half at 0.989 with 0 refused; the *execution* half's gate (malformed-call
   rate and tokens against the code incumbent, where the call is not a copy) is
   unbought.
5. **What real data with a mechanical verifier exists** that could open the window
   for M2? That, and only that, spends the last redesign.

## 5. Review received the same day, and what it corrected

An outside reviewer compared this report to the plan phase by phase and found the
execution faithful **and one argument wrong**: §2c dismissed *training the 32B as a
target* (option A) with *"leaves the ordering trivial"*. That conflates two things.
**The ordering between grades is decided by the material's difficulty, not by the
target**; a trained target *enables* the window $Q(T) \ge \max Q(E)$ rather than
closing it. What the two runs prove is narrower than §2a said: **the window does not
exist in two easy regions with an untrained target** — not that no generated suite can
contain it. The valid arguments against A are others: the distillation confound if the
corpus is written by the target, a new C18 risk in serving a LoRA on an AWQ base, and a
session's cost.

**So M2 is not closed — it is reopened as one arm** (the reviewer's step 3: a 32B
trained on the desk, a deeper `commitment` band where trained grades do not saturate,
M-target re-run under §7.2's `≥`), spending a brazo, not the last redesign. The plan's
Phase 4 row, `CLAUDE.md` §8 and the README carry the correction. Two smaller points
also adopted: the empty-arm fault of P58 lived in all three C18 gates (fixed, #212),
and the gate now follows §7.2 literally (`≥`), with acceptance measurable as a
*descriptive* number when the gate refuses (`--accept-anyway`).
